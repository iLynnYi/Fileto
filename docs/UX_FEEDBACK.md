# Fileto 操作提示规范

本规范用于 Fileto 后续界面实现与审查，适用于文件类型查询、应用反向查询、修改、批量操作、历史和条件恢复。规则描述目标行为，不代表现有界面均已完成适配。

提示反馈一次操作；当前默认应用、候选范围、查询状态和逐项处理结果由实际数据决定。临时消息消失不会改变这些状态。

## 呈现方式

| 情况 | 呈现 | 结束条件 |
| --- | --- | --- |
| 手动刷新完成、补充查询完成等已确认的普通结果 | 窗口内内容顶部居中的紧凑悬浮消息（Message / Toast），不挤占页面布局 | 默认 5 秒后自动消失；用户可提前关闭 |
| 类型发现、查询、修改或恢复正在处理 | 操作控件附近或现有进度区域显示实际进度，防止重复提交 | 本次处理结束后更新为实际结果；等待系统确认期间保持进行中 |
| 扩展名无效等可修正输入错误 | 对应输入位置显示错误和修正示例 | 用户修正输入或重新提交后更新 |
| 修改默认应用 | 行内菜单选择候选即提交；“其他应用…”与批量保留应用选择界面及影响说明，分别点“修改”／“开始修改” | 执行前重新检查当前关联与候选；有选择弹窗时等待实际关闭 |
| 恢复或失败项重试 | 原生预览弹窗说明对象、目标应用、影响和跳过项，以明确按钮确认 | 用户确认或取消；执行前等待预览弹窗实际关闭 |
| 查询失败、结果待验证或历史读写失败 | 对应详情、刷新提示或结果区域保留影响与下一步；临时消息可同时提醒 | 新的可信结果确认问题已解决后更新 |
| 普通单项修改成功或已是默认 | 更新列表，以短消息显示扩展名与目标应用，不另弹结果；仍保留操作记录 | 默认 5 秒后消失，也可关闭；详情与恢复通过历史查看 |
| 失败、取消、冲突、待验证、历史保存失败，以及批量修改、恢复与重试的结果 | 现有逐项结果界面及操作记录 | 用户关闭结果界面；已保存记录按历史保留规则管理 |

自动刷新正常完成时静默更新，不每 30 秒弹出成功消息。自动刷新失败保留旧结果和可见的刷新提示；同一持续故障不反复弹出相同消息。

## 临时消息的统一样式

- 由窗口统一管理，文件类型与应用视图复用同一套消息；切换视图不让正在显示的提示突然消失。弹窗内操作的反馈在用户当前操作的窗口内容中可见。
- 相同重复结果可合并，连续操作不堆叠遮挡内容；不为各视图增加常驻操作成功栏，也不另开桌面浮窗。
- 使用小型圆角容器，包含结果图标、简短文字和独立关闭按钮。关闭按钮有明确的辅助技术名称。
- 短文案按内容收紧宽度，最大宽度为 360 pt；窄窗口进一步收窄，避开顶部主要操作按钮。长文案换行，不用省略号隐藏失败原因或下一步。
- 沿用系统主题、轻微底色和阴影，适配浅色与深色模式；以图标和文字共同区分结果，不只依靠颜色。
- 显示和关闭使用短暂淡入淡出，尊重系统减少动态效果设置；消息能被辅助技术读出，不抢走输入焦点。

## 文案与成功依据

普通提示使用“动作 + 结果”，失败提示补充可执行的下一步。优先中文状态摘要，不直接拼接原始系统错误。

修改和恢复的成功依据是系统读回的默认应用。执行结束后直接使用执行前检查与读回得到的系统查询快照更新本次涉及的类型，展示结果，不等待重新发现应用或全量刷新；查询失败保留最近可信值与故障说明，不影响其他类型的已有查询提示。请求已发出、系统接受设置、读回目标应用和操作记录已保存是不同结果，文案须分别表达。

| 结果或场景 | 提示规则与示例 |
| --- | --- |
| `changed` | 只有读回目标应用才显示“已修改并验证”；恢复流程可显示“已恢复并验证” |
| `alreadyDefault` | 显示“已是目标应用，无需修改”，不计入本次修改数量 |
| `unverified` | 显示“系统已接受设置，尚未验证生效。请刷新检查”，不能报成功，也不能断言没有修改 |
| `conflict` | 显示“默认应用在预览后发生变化，本项未修改。请重新预览” |
| `failed` | 显示具体影响和适用的下一步，如“目标应用已不可用，请重新选择应用”；技术错误按需查看 |
| 系统或用户取消 | 显示“已取消这次设置”，与普通失败区分；不承诺系统配置已回滚 |
| 停止后的未执行项 | 显示“已停止后续修改，此项未执行”，与当前项的系统取消区分 |
| 恢复预览跳过项 | 说明原应用不可用、没有可恢复记录或当前关联已变化，不笼统宣称已经恢复 |
| 历史保存失败 | 显示“修改结果仍可查看，但操作记录保存失败”，不得把关联修改误报为失败，也不得承诺记录已保存 |

批量摘要分别表达已修改、无需修改、待验证、冲突、失败与取消数量，并保留预览中未进入执行的跳过项说明。例如：“2 项已修改并验证，1 项待验证，1 项未执行”。部分成功不显示“全部成功”，逐项结果始终可查看。

批量选择应用时显示预计需修改、已是目标应用和不受支持的数量；这些数量只是当前查询的预览，不能描述为已完成。没有需修改项时禁用修改按钮并说明原因。所选类型通过独立表格查看扩展名、文件类型、当前默认应用与逐项处理方式，关闭明细后保留应用选择，避免挤压候选列表。应用图标保持原色，菜单按下与行选中状态由控件和行背景表达。

批量候选查询显示“已查询 X / Y 个类型”，提交前准备计划显示“已准备 X / Y 个类型”；处理期间不能重复提交。查询进度表示已处理的查询数量，失败结果仍须单独说明，不能当作修改成功数量。

超时、连接或查询异常不能证明已提交的设置被取消。遇到结果未知时，先提示刷新核对；重新操作通过现有预览流程，不自动重放修改。

## 进度、确认与条件恢复

修改按类型顺序执行。进度区显示已处理数量和总数，等待系统确认时说明“请在 macOS 提示中确认或取消”，不能只显示无法判断的“处理中”。

“停止后续修改”只阻止后续项。点击后显示“将在当前项结束后停止”，保留已经完成的结果；不承诺撤销前面的修改或关闭正在进行的系统确认。

行内菜单直接选择系统候选应用后提交，不再打开选择或预览弹窗。菜单只保留候选应用、当前默认标识和“其他应用…”入口，不堆放操作说明。受影响扩展名在类型表格中展示，多类型说明通过现有详情入口查看；等待系统设置时再提示用户完成 macOS 确认。执行计划保留用户看到的默认应用快照；执行前重新查询，发现冲突时跳过，不能静默替换快照后覆盖。普通单项成功或已是目标应用时更新列表并显示短提示；失败、取消、冲突、待验证与历史保存失败仍打开结果详情。

“其他应用…”及批量修改将预览合并到应用选择界面，说明目标应用、共享同一类型的扩展名共同受影响、具体文件可能有独立打开方式，以及哪些项目不会处理。单项按钮使用“修改”，批量使用“开始修改”，不另弹同义确认。批量开始前明确提示“macOS 可能逐项要求确认，需手动完成”，不能承诺一次授权整批。恢复与失败重试仍使用独立预览及“确认恢复”／“确认修改”按钮。macOS 系统确认由用户完成。

恢复是重新设置修改前的应用，需要重新检查候选范围和当前关联，再按普通执行流程验证。当前关联已经偏离记录目标时跳过，明确说明保留用户后续修改；不把恢复描述为系统事务回滚。

## 持续状态与技术详情

当前默认应用、候选列表、上次刷新时间、查询故障、文件查询旧结果标记和逐项结果可持续展示。“查询完成”“已保存”等一次操作反馈按临时消息处理。

查询失败时保留旧结果，并说明它是上次查询值；新的可靠查询成功后再更新故障。没有默认应用、动态类型和查询失败分别表达，不据此提示系统关联损坏或引导重建数据库。反向查询只说明已发现类型的范围。

类型列表的问号和信息图标位于扩展名旁，支持点击。“未声明类型”和“同扩展名对应多种类型”的原因与处理建议通过窗口顶部居中的 Message 展示，默认 5 秒后消失，也可手动关闭；连续点击替换当前消息并重新计时。悬停说明作为补充，不单独增加提示列。

默认展示用户可理解的原因、影响和下一步。UTI、Bundle ID、完整路径及系统错误域／错误码放在现有“高级信息”或“错误详情”等按需展开区域，支持选取复制。应用选择或同名应用辨别确实需要路径时，可在对应选择区域显示；短暂消息不堆放技术数据。

文件类型详情的“高级信息”使用字段和值两列对齐的表格，逐行展示 UTI、状态、系统候选应用数量，以及可用默认应用的 Bundle ID 和应用路径。长值允许换行并支持选取复制，表格底色和分隔线沿用系统主题。

操作结果和历史是当时的记录，不冒充当前系统状态；自动刷新不改写已有预览、历史及结果快照。历史读取失败不显示为“还没有修改记录”，应明确区分读取失败与确实无记录。

提示不包含被查询文件的内容、凭据或内部原始数据。macOS 系统通知不替代窗口内操作反馈；本规范不新增后台通知能力。

## 原生交互与验收

输入框保留 ⌘C、⌘X、⌘V、⌘A 与右键编辑菜单，校验错误允许在原位置修正和重试。按需展开区域的标题与箭头共同可点击，保留键盘操作和辅助技术的展开状态。

后续实现按以下场景验收，结果与本机截图记录放入 `docs/local/`：

- 普通结果到期或关闭、重复消息合并、视图切换、窄窗口、长文案及浅色／深色主题。
- 输入错误原位修正，操作期间阻止重复提交，等待系统确认时进度与停止语义准确。
- 单项成功、已是默认、待验证、冲突、失败、系统取消及批量部分成功分别表达。
- 历史读写失败不覆盖真实修改结果；查询故障关闭消息后仍保留，重新查询成功后正确更新。
- 条件恢复跳过后续已被用户修改的关联，历史与当前状态分别表达。
- 消息读出、关闭按钮、键盘与减少动态效果设置通过真实桌面检查。

系统写入验收使用专用测试类型，流程见 [实现与验证](verification.md)。本规范的文档检查不替代上述界面与系统验收。
